## 1. Introduction

**What are Logs?**

Logs are records of events generated by operating systems, applications, network devices, security tools, and cloud platforms.

They help security teams understand what happened, when it happened, and where it happened.

### Why are Logs Important?

- 🔍 Monitor user and system activities.
- 🛡️ Detect suspicious behavior and potential threats.
- 🔐 Identify unauthorized access.
- 🚨 Investigate security incidents.
- 📊 Maintain visibility across IT infrastructure.

---

## 2. Log Types Overview

| Log Category | Common Sources | Primary Purpose |
|---|---|---|
| System Logs | Windows Event Logs, Linux Syslog, macOS | Monitor system events and errors |
| Security Logs | Firewall, IDS/IPS, EDR, Antivirus, PAM | Detect threats and unauthorized access |
| Application Logs | Apache, Nginx, IIS, Applications | Monitor application activity and errors |
| Network Logs | Routers, Switches, DNS, NetFlow, Firewall | Analyze network traffic |
| Cloud Logs | AWS CloudTrail, Azure Activity Logs, GCP Audit Logs | Monitor cloud activities and changes |

## 3. Detailed Log Categories

### 3.1 Web Server Logs

**Purpose:** Track web server requests and user activity.

**Common Sources:**
- Apache
- Nginx
- IIS

**What They Reveal:**
- HTTP requests
- Client IP addresses
- Requested URLs
- HTTP response codes

**SOC Use Cases:**
- Identify suspicious web requests.
- Investigate unusual IP addresses.
- Detect potential web attacks.

---

### 3.2 Authentication Logs

**Purpose:** Understand who accessed a system and when.

**Common Sources:**
- Active Directory
- RADIUS
- LDAP

**What They Reveal:**
- Successful and failed logins.
- Account activity.
- Authentication patterns.

**SOC Use Cases:**
- Detect brute-force attacks.
- Investigate repeated failed logins.
- Identify unauthorized account access.
- Monitor suspicious login patterns.

---

### 3.3 DNS Logs

**Purpose:** Understand domain lookups and where network connections are going.

**Common Sources:**
- DNS Servers
- DNS Resolvers
- Recursive Resolvers
- Firewall DNS Logs

**What They Reveal:**
- Queried domains.
- DNS resolution activity.
- Suspicious domain lookups.

**SOC Use Cases:**
- Identify suspicious domains.
- Investigate phishing-related domains.
- Detect potential DNS tunneling.
- Monitor unusual DNS queries.

---

### 3.4 Cloud Logs

**Purpose:** Monitor cloud activities and resource changes.

**Common Sources:**
- AWS CloudTrail
- Azure Monitor / Activity Logs
- GCP Audit Logs

**SOC Use Cases:**
- Monitor API calls and user activities.
- Track resource configuration changes.
- Detect unauthorized access.
- Identify privilege escalation.
- Support compliance audits.

---

### 3.5 Application Logs

**Purpose:** Understand application behavior and troubleshoot issues.

**Common Sources:**
- Web Applications
- Databases
- Custom Applications
- Application Frameworks

**SOC Use Cases:**
- Investigate user activities.
- Identify application errors.
- Detect SQL Injection and XSS attack patterns.
- Monitor API abuse.
- Investigate application performance issues.

---

### 3.6 Network Logs

**Purpose:** Understand network traffic flow and communication.

**Common Sources:**
- Routers
- Switches
- IDS/IPS
- Firewalls
- NetFlow
- Proxy Servers

**SOC Use Cases:**
- Analyze network traffic.
- Detect suspicious connections.
- Investigate lateral movement.
- Identify possible data exfiltration.
- Monitor bandwidth usage.
- Detect network anomalies.

---

### 3.7 Endpoint Logs

**Purpose:** Maintain visibility into activities occurring on individual devices.

**Common Sources:**
- Windows Event Logs
- Linux Syslog
- EDR
- Antivirus

**SOC Use Cases:**
- Monitor process execution.
- Detect malware activity.
- Investigate privilege escalation.
- Track user activity.
- Identify suspicious endpoint behavior.

---

### 3.8 Database Logs

**Purpose:** Track database access, queries, and modifications.

**Common Sources:**
- MySQL
- Microsoft SQL Server
- PostgreSQL
- Oracle
- MongoDB

**SOC Use Cases:**
- Monitor database queries.
- Detect unauthorized access.
- Investigate suspicious data modifications.
- Identify possible data exfiltration.
- Monitor unusual database activity.

---

## 4. Quick Reference

| Log Type | What to Investigate |
|---|---|
| Web Server | HTTP requests, IPs, URLs, response codes |
| Authentication | Failed logins, successful logins, account activity |
| DNS | Suspicious domains, DNS queries, tunneling |
| Cloud | API calls, resource changes, user activity |
| Application | Errors, SQL Injection, XSS, API abuse |
| Network | Traffic patterns, suspicious connections, data transfer |
| Endpoint | Process execution, malware, user activity |
| Database | Queries, unauthorized access, data modifications |

---

## 5. Key Takeaways

- Different log sources provide different perspectives.
- Authentication logs help investigate login activities.
- DNS logs help identify suspicious domain lookups.
- Network logs provide visibility into traffic flow.
- Endpoint logs help investigate suspicious device activities.
- Cloud logs help monitor cloud infrastructure.
- Correlating multiple log sources helps build a clearer picture of security incidents.

> **Different Logs. Different Perspectives. Greater Visibility.**
