## 📌 1. Introduction

Logs are records of activities and events generated by operating systems, applications, and network devices.

SOC Analysts use logs to:

- Monitor system activities.
- Detect suspicious behaviour.
- Investigate security incidents.
- Identify unauthorized access.
- Understand what happened during an attack.

**Why are logs important?**

Without proper logging, security analysts may miss important events and struggle to investigate incidents.

---

## 🛠️ 2. Tools for Viewing and Analyzing Logs

### 01. Windows Event Viewer

**Purpose:** View and analyze Windows event logs.

Windows Event Viewer helps analysts investigate system, security, and application events.

**Command to open:**

```cmd
eventvwr.msc
```

**SOC Use Case:**
- Investigate Windows login activities.
- Review system errors.
- Monitor security-related events.

---

### 02. Linux Log Monitoring

**Purpose:** View logs using Linux command-line tools.

Linux stores system and application logs that help analysts understand system activities.

**Important commands and locations:**

| Command / Location | Purpose |
|---|---|
| `journalctl` | View systemd journal logs |
| `journalctl -xe` | View recent journal messages with explanations |
| `/var/log/` | Directory containing system log files |

**SOC Use Case:**
- Investigate authentication activities.
- Check system events.
- Troubleshoot suspicious activities.

---

### 03. Wireshark

**Purpose:** Analyze network packets and network traffic.

Wireshark is a network protocol analyzer used to capture and inspect network packets.

**SOC Use Case:**
- Capture network packets.
- Inspect network communication.
- Investigate suspicious network traffic.

### 04. ELK Stack

| Component | Function |

**Purpose:**

Search, visualize, and analyze logs at scale.

**SOC Use Case:**

## ⚠️ 3. Common Logging Mistakes to Avoid

Proper logging is important for reliable security monitoring.

### 01. Logging Not Enabled on Endpoints

**Problem:**

Critical logs, such as EDR and Sysmon logs, may not be enabled on systems.

**Impact:**
- Important activities may not be recorded.
- SOC analysts may miss suspicious events.

**Best Practice:**

Enable and verify logging on all endpoints.

---

### 02. Log Retention Too Short

**Problem:**

Logs are overwritten or deleted before an investigation takes place.

**Impact:**
- Historical evidence becomes unavailable.
- Incident investigations become difficult.

**Best Practice:**

Maintain appropriate log retention policies according to organizational policy and compliance requirements.

---

### 03. Log Overload / No Filtering

**Problem:**

Too many logs and unnecessary events create noise.

**Impact:**
- Important security events get missed.
- Analysts may struggle to identify real threats.

**Best Practice:**

Use:
- Proper log filtering.
- Relevant use cases.
- Alerting rules.

---

### 04. Not Monitoring Critical Event IDs

**Problem:**

Important events are not monitored.

**Examples:**
- Authentication failures.
- Privilege changes.
- Suspicious login activities.

**Impact:**

Potential security incidents may go unnoticed.

**Best Practice:**

Monitor important Event IDs and build detection rules.

---

### 05. Logs Not Protected from Tampering

**Problem:**

Logs can be modified or deleted by attackers.

**Impact:**
- Evidence can be destroyed.
- Investigation reliability decreases.

**Best Practice:**

Use:
- Secure log storage.
- Write-once controls.
- Proper access controls.
- Log integrity protection.

---

## 🔐 4. Key Takeaways for SOC Analysts

Reliable SOC investigations require logs that are:

| Requirement | Importance |
|---|---|
| Enabled | Capture important activities |
| Retained | Preserve historical evidence |
| Filtered | Reduce unnecessary noise |
| Monitored | Detect critical security events |
| Protected | Prevent unauthorized modification |
